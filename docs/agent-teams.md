# 单 Agent、同模型团队与异模型团队

桌面 0.10 增加两种实验性团队模式。默认仍是单 Agent；选择思考强度不会自动启动成员。CLI 与桌面使用同一套 AgentService、模型绑定、团队调度、上下文权限、工具循环和预算。

| 模式 | 执行方式 | 适合先尝试的任务 |
| --- | --- | --- |
| 单 Agent | 一个主 Agent 正常回答、调用获授权工具 | 简单问题、连续交流、时延敏感的学习 |
| 同模型团队 | 主模型分工，两个相同实际模型的独立成员核查，主模型综合 | 有可独立核查的推导、代码或约束 |
| 异模型团队 | 主模型分工，不同模型分别核查，主模型综合 | 希望比较不同模型的推理与遗漏点 |

“适合尝试”不是质量提升结论。成员多并不保证更正确，团队通常需要更多调用。实际质量、完整率和耗时以[评测协议](agent-team-evaluation-protocol-20260909.md)及[96 个真实留出任务对照](evidence/team-quality-comparison-20260909.md)为准；原可行性研究保留在[研究报告](agent-team-feasibility-20260909.md)。

## 桌面使用

输入框下方选择三种协作模式。团队配置可选择核查职责、异模型成员的连接、并发数及时间上限。动态添加的 API 连接也会出现在成员选择器中，不需要为每家模型重新开发。主模型为 Pi 时，异模型默认选择 DeepSeek 与 Kimi；同模型模式固定主模型的实际型号，同一次任务不会因中途修改 Pi 设置而换型号。

团队默认只向成员发送当前问题和本次图片。“允许团队成员使用本会话历史及已授权的资料、项目和外部查询”开启后，成员才可使用这些内容；仍须先取得本会话本来的访问授权。跨模型发送也受这一开关控制。所有成员都只读，不能审批、保存学习产物、修改项目或继续招募成员。正式写入仍由主 Agent 经原审批执行。

团队卡片默认折叠。展开可以查看实际模型、具体分工、状态、耗时与成员结论，也可停止一个成员。主停止按钮会取消整个任务。成员输出作为候选分析交给主 Agent；工具证据和课程验收不能由成员文字代替。

中断或成员失败时，完整团队不会被标为完成。继续旧任务会复用已经保存的结论，未确认完成的成员不自动重新收费调用。需要重新请求全部成员时，点击“重新运行整个团队（新任务）”；原任务及失败记录保留。切换模式或模型的配置对新任务生效，旧任务继续使用原绑定，权限改变时要求发起新任务。

## CLI 使用

```text
/mode single
/mode same
/mode mixed
/team
/team stop <成员 ID>
```

模式会保存在当前 CLI 工作区的公开偏好中。`/team` 显示配置和最近团队的模型、成员结论及用量；运行过程中也可查看或停止成员。高级公开配置使用 `/team config <JSON>`，例如：

```text
/team config {"mode":"mixed-model-team","members":[{"role":"reasoning-checker","provider":"deepseek-api"},{"role":"material-checker","provider":"kimi-api"}],"shareContext":false}
```

Key 继续走各入口已有的安全存储；上面的 JSON 不接受密钥。同样的运行策略不意味着两个入口的独立偏好目录或凭据文件会自动复制。

## 有界行为与限制

每题默认最多十二次模型请求、二十四次工具请求、16384 输出 token 预留和 192000 输入 token 估算；实际已报告用量另外显示，缺失用量保留为未知。分工单次最多 1024 输出 token，成员与综合单次最多 4096，并受具体模型能力及共享剩余额度进一步限制。输入估算不是精确计费分词，订阅成本不视为零。

默认成员时限 90 秒，整题 240 秒。系统连接准备计入整题时间，在准备完成后才开始成员计时。最多两个成员同时执行；同一 Pi 订阅连接暂串行调度，避免同时启动原生请求造成争用。成员采用独立任务 ID、模型历史和 ToolHarness，复用单 Agent 的有界循环、引用核对与格式检查。

第一版采用一轮分工与独立核查，不支持递归、成员自由通信、动态任务依赖图、自动多轮补查或团队写入。团队记录直接进入现有原子会话存储和完整工作区备份，不另建会话真相。恢复导出的工作区不会重新授权或自动运行旧成员；旧绑定范围不符时明确拒绝继续。历史会话没有团队字段时仍按单 Agent 处理。启用团队时会话升级为 v9，并保留原格式副本；旧版本将拒绝打开该会话，避免写回时丢失团队记录和预算。

已有教学效果试验需要保持原实验条件，因此试验会话不接受团队模式。本文的回答质量对照也不能替代真实学习者的学前、学后与延迟复习验证。
