# 单 Agent、同模型团队与异模型团队

桌面 0.10 增加两种实验性团队模式，0.11 开发版已加入任务依赖、成员工作上下文、实际工具回执、逐项审查与定向恢复。默认仍是单 Agent；选择思考强度不会自动启动成员。CLI 与桌面使用同一套 AgentService、模型绑定、团队调度、上下文权限、工具循环和预算。

| 模式 | 执行方式 | 适合先尝试的任务 |
| --- | --- | --- |
| 单 Agent | 一个主 Agent 正常回答、调用获授权工具 | 简单问题、连续交流、时延敏感的学习 |
| 同模型团队 | 相同实际模型按不同核查方法独立报告，审查分歧、必要时复核后综合 | 有可独立核查的推导、代码或约束 |
| 异模型团队 | 不同模型独立提供证据与候选结论，审查分歧、必要时复核后综合 | 希望比较不同模型的推理与遗漏点 |

“适合尝试”不是质量提升结论。成员多并不保证更正确，团队通常需要更多调用。0.11 的[本轮实现与验收状态](evidence/team-quality-optimization-20260910.md)包含已完成的 32 个新题对照，以及协议补修后仍待完成的真实回归。开发前的差异和归因见[团队架构报告](agent-team-architecture-review-20260910.md)；本轮落地架构见[内核设计](agent-team-kernel.md)，进度与验证见[实施计划](agent-team-kernel-plan-20260910.md)及[证据](evidence/team-kernel-alignment-20260910.md)。历史模型分数不适用于本轮新内核。0.10 的历史质量、完整率和耗时见[评测协议](agent-team-evaluation-protocol-20260909.md)及[96 个真实留出任务对照](evidence/team-quality-comparison-20260909.md)为准；原可行性研究保留在[研究报告](agent-team-feasibility-20260909.md)。

## 桌面使用

输入框下方选择三种协作模式。团队配置可选择核查职责、异模型成员的连接、并发数及时间上限。动态添加的 API 连接也会出现在成员选择器中，不需要为每家模型重新开发。主模型为 Pi 时，异模型默认选择 DeepSeek 与 Kimi；同模型模式固定主模型的实际型号，同一次任务不会因中途修改 Pi 设置而换型号。

团队默认只向成员发送当前问题和本次图片。“允许团队成员使用本会话历史及已授权的资料、项目和外部查询”开启后，规划、成员、审查共用同一份有界历史任务包，成员才可使用已授权工具；主 Agent 系统指令不进入任务包，历史仅作不可信资料；仍须先取得本会话本来的访问授权。跨模型发送也受这一开关控制。所有成员都只读，不能审批、保存学习产物、修改项目或继续招募成员。正式写入仍由主 Agent 经原审批执行。

团队卡片默认折叠。展开可以查看实际模型、具体分工、状态、耗时、结论与依据、分歧审查和定向复核，也可停止一个成员或其正在执行的复核。主停止按钮会取消整个任务。成员输出作为候选分析交给主 Agent；工具证据和课程验收不能由成员文字代替。首轮结果不会被后续意见覆盖，方便比较更正前后的依据。

0.11 的成员设置支持单独选择思考程度和输出上限，默认自动匹配成员思考档位，具体规则见下方有界行为。不同服务商的同名思考预设不代表相同计算量。调高单次输出不会提升整题总预算，最终回答和审查仍有容量预留。

展开“任务与依赖”可以查看交付条件、前置任务和每次执行次数；“待核查 / 已逐项模型审查 / 已关联实际工具依据”与流程完成状态分别显示。模型意见及工具成功都不等于正确性认证。

中断或成员失败时，完整团队不会被标为完成。继续旧任务会复用已经保存的结论，未确认完成的成员不自动重新收费调用。新内核的失败任务可点击“补做此任务”，只重试所选任务以及尚未执行的阻塞依赖分支，再审查和综合；每项最多执行三次，沿用原累计预算，可能再次计费，旧未知用量不会清零。依赖未完成时先补前置任务。需要重新请求全部成员时，点击“重新运行整个团队（新任务）”；原任务及失败记录保留。切换模式或模型的配置对新任务生效，旧任务继续使用原绑定，权限改变时要求发起新任务。

## CLI 使用

```text
/mode single
/mode same
/mode mixed
/team
/team stop <成员 ID>
/team retry <任务 ID>
```

模式会保存在当前 CLI 工作区的公开偏好中。`/team` 显示配置、任务 ID 与依赖、核查覆盖、最近团队的模型、成员结论及用量；运行过程中也可查看或停止成员。高级公开配置使用 `/team config <JSON>`，例如：

```text
/team config {"mode":"mixed-model-team","members":[{"role":"reasoning-checker","provider":"deepseek-api"},{"role":"material-checker","provider":"kimi-api"}],"shareContext":false}
```

Key 继续走各入口已有的安全存储；上面的 JSON 不接受密钥。同样的运行策略不意味着两个入口的独立偏好目录或凭据文件会自动复制。

## 有界行为与限制

每题默认最多十二次模型请求、二十四次工具请求、16384 输出 token 预留和 192000 输入 token 估算；实际已报告用量另外显示，缺失用量保留为未知。分工单次最多 1024 输出 token，审查最多 2048，成员与综合默认单次最多 4096；成员可显式配置最多 16384，或选择自动分配，仍受具体模型能力及共享剩余额度进一步限制。整题输出预算可在设置中选择 16384、24576、32768 或 48000；提高预算由用户选择，不因调用失败自动增加。输入估算不是精确计费分词，订阅成本不视为零。API 截断等失败仍保留服务商已经报告的用量。

新任务先固定实际模型，再按适配器能力选择成员资源策略。对声明推理与正文共享额度的 DeepSeek/Kimi Chat Completions 连接，自动档位按快速 4096、均衡 8192、深入 16384 token 的本地建议目标匹配；预算不足时降低自动档位。默认两名成员、16384 整题预算下使用快速档；24576 可让两名均衡成员各获得 8192 单次上限。明确设置的成员档位优先，预算不足时显示风险。原生 Codex 与未知能力保持原策略，主 Agent 档位不变。DeepSeek 快速关闭额外思考，Kimi K3 快速仍使用 low 推理；服务商间标签相同不代表算力相同。较低档位可能影响准确性，不能只按完成率评价质量；详见[本轮策略与验收](evidence/team-resource-budget-20260911.md)。

0.11 新配置默认成员时限 180 秒，整题 240 秒；已经保存的 90 秒等设置保留，可在团队配置调整。模型适配器自己的超时也有效，不能仅靠增大成员期限覆盖服务商限制。系统连接准备计入整题时间，每个连接最多准备30秒，在准备完成后才开始成员计时。成员连接准备失败不阻止健康分支；必需成员缺失仍使流程不完整，主连接失败则停止调度。最多两个成员同时执行；同一 Pi 订阅连接暂串行调度。成员采用独立任务 ID、模型历史和 ToolHarness，复用单 Agent 的有界循环。内部报告有单独 schema，不会套用用户最终正文的段落规则；不合格式最多修正一次，仍不合格则保留失败状态。

每轮先创建最多4项结构化任务，含目标、成员编号、依赖与交付条件；无依赖成员独立执行，有依赖任务只在前置成功后执行，同一成员不并行。每名成员可使用自己的最近工作产物及明确依赖的结果；每个阶段仍使用共享受控循环与独立持久执行 ID，最多6轮并受整题预算约束。主模型审查后至多追加一个定向复核任务，成功后再审查一次，团队累计最多8项任务。不开放无限辩论、递归、自由通信或成员写入。工具回执由执行器生成，报告只能引用实际成功回执；纯推理不伪造工具依据。交付条件未覆盖、依据仍不确定时保留待核查；后续修正通过 sourceTask 指向新依据，不覆盖旧报告。

团队记录直接进入现有原子会话存储和完整工作区备份，不另建会话真相。恢复导出的工作区不会重新授权或自动运行旧成员；中断的审查与复核也不会自动重发。旧绑定范围不符时明确拒绝继续。历史会话没有团队字段时仍按单 Agent 处理。旧团队会话仍可读取为 v9；早期0.11复核记录为 v10，新内核记录为 v11，含原生执行预算为 v12，含成员资源策略为 v13；保存前保留原格式副本，旧版本拒绝覆盖新格式。恢复任务保持已保存档位与预算，不应用新策略。不会补做旧任务缺失的审查。

研究选择、实现边界见[质量设计](agent-team-quality-design-20260909.md)。V2 的 96 任务是历史基线；本轮新对照条件见[V3 预注册](agent-team-quality-evaluation-protocol-20260909.md)，不把工程回归通过等同于模型收益。

已有教学效果试验需要保持原实验条件，因此试验会话不接受团队模式。本文的回答质量对照也不能替代真实学习者的学前、学后与延迟复习验证。
