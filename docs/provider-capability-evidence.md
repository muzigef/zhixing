# 接入能力的声明与实测证据

2026-09-18。配置/模板中的工具、图片、窗口和输出上限仍是 adapter_policy，连接测试不会自动提高权限、预算或修改能力配置。

## API

设置中保留「测试连接」，另有可选「测试工具能力」（自定义连接需先声明启用工具）：

- 文本测试只验证固定公开问题得到完整非空正文；图片、工具、真实窗口和服务端输出限制均不因文本成功而变成已验证。
- 工具测试最多两轮逻辑模型调用，仅提供一个无副作用的合成工具。首轮须调用该工具且为空参数，第二轮须使用工具返回的随机 nonce；不调用文件、网络、学习或其他真实工具。
- 未调用工具或未复述返回值是 inconclusive；多工具、未知工具、非空参数、截断或无完整结束仍失败。总时限 60 秒、最多 4000 可见字符，每轮最多请求 2048 输出 tokens，受连接更低的配置限制。传输重试继续服从共享有界重试策略；两轮不是所有 HTTP 尝试的计数。
- 回执保留检查时间、声明的策略、请求模型、服务端显式返回的模型名、实测维度和轮数。没有响应 model 字段则保留未报告，不用配置模型或 usage.model 冒充。模型名仍是服务端自报，不是身份认证或路由证明。
- 不保存测试正文、随机 nonce 或密钥，不携带用户对话/学习资料；可能产生 API 用量。结果仅代表这次有限探针，不能证明长任务、全部工具/图片或大窗口稳定可用。

三种协议均由真实适配器走两轮 HTTP 夹具核对工具返回关联与模型字段；没有把这些夹具当作真实三家连接或质量实测。首正文耗时单列，旧 firstTokenMs 仅作兼容别名，不表示真实 token 时钟。

## 官方运行时

「检查官方 Agent」和下面的 CLI 只运行帮助/版本检查，不读取账号文件，不调用模型：

```sh
node --import tsx scripts/probe-native-runtime.ts --vendor=codex --output=new-runtime-receipt.json
```

Codex 保持 0.153.4 的验收白名单；未知版本显示实际可解析版本但不放行。Claude 记录进程版本及必要参数兼容性，不能把参数存在当成真实订阅或同等强度的版本验收。未能取得版本不编造版本号，原始进程输出不写入回执。执行时仍重新核对，未加入会绕过版本检查的缓存。
