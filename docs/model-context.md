# 模型能力与上下文管理

模型通道显式描述文本输入、工具续轮、输出上限配置及应用上下文上限。当前 Pi 桌面与 DeepSeek 支持受控工具续轮，CLI Pi 仍为仅文本通道。图片粘贴/文件拖入聊天显示尚不支持，不读取附件或用文本冒充图像输入。这里的 48,000 Token 是知行预算策略，不是对具体商业模型最大窗口的宣称。

桌面「设置 → 偏好」可降低上下文预算和回答预留；两种主力模型的输出上限会传到实际请求。默认保持总窗口 48,000、回答预留 16,384。CLI 可通过 `ZHIXING_CONTEXT_WINDOW_TOKENS` 与 `ZHIXING_OUTPUT_TOKENS` 配置，范围同样不能超过原策略。CLI Pi 不支持独立调整输出限制，必须保持其原有 16,384 预留；小窗口不足时明确失败。较低输出上限可能导致长回答未完成，不能把这种截断标记为完成。

字符估算是规划近似。拿到真实输入用量后，当前执行段后续请求会保守增加估算系数（最高 4），不会调高预算。诊断保留该次估算与实际报告；尚无报告不伪造 Token。Pi SDK 的非缓存输入、缓存读取、缓存写入相加成为总输入，DeepSeek 的输入本身已是总数，两者口径一致。Pi worker 还会按所选模型的公开元数据复核窗口和输出上限。

压缩只产生发给模型的视图，原会话和工具调用/结果配对留在本地。结构化上下文保留目标、约束、明确纠正的消息 ID、未完成任务及摘要来源范围；模型摘要标注未验证。旧反馈只保留最近四段有界片段，防止反馈本身撑爆上下文。

模型在缺少旧信息时可调用 `read_conversation_history` 或 `read_execution_history`，分别按消息或执行轮次分页。返回原文 JSON 片段、来源 ID/哈希和后续游标；续页必须验证哈希。模型不能指定另一会话/任务，执行记录仍受资料授权检查。读取历史不授予执行权限，旧回答不变成验证事实。

续接任务时，最新受控观察替换模型视图中的旧观察；原始日志保持不变。这使学习记录的更正、撤回和目标修订能生效，不因旧提示词仍存在就重新使用已过期的学习快照。

启用本机语义检索后，服务不可用或当前模型没有有效索引时继续使用关键词结果；受控上下文会包含明确降级状态，任务活动也会显示原因，不将关键词结果冒充语义命中。取消信号仍直接结束检索，不会被当作普通降级继续执行。
