# 知行项目面试准备

这套材料面向中高级 Agent 应用开发与架构岗位，按项目源码、真实验证记录和公开招聘要求整理。先理解与演练，再用自己的语言回答；它不是公司实际面试题泄露，也不代替现场编程练习。

内容核对日期：2026-09-14；实现基线：`485b358`。招聘样本仍保留 2026-09-11 的检索日期。

## 先用 30 分钟建立整体认识

下面的简答可以直接复述，再按右侧索引展开。时间是练习安排，不是保证掌握所需的时间。

| 用时 | 核心问题 | 先掌握的答案 | 完整答案与实现索引 |
| --- | --- | --- | --- |
| 0–5 分钟 | 知行解决什么问题，为什么不是普通聊天？ | 知行围绕资料学习、实践、独立作答和延迟复习组织流程；通用执行能力由模型调用、工具、状态和恢复组成，业务价值取决于用户是否学会，不能仅看答案生成成功。 | [Q01](question-bank.md#q01)、[Q55](question-bank.md#q55)、[项目口述](system-design.md#presentation) |
| 5–10 分钟 | 为什么既有 ModelClient 又有 AgentExecutor？ | API 返回本轮文本或工具提议，由知行继续执行循环；官方运行时自己拥有任务执行流程。两种接口分开后，公共层不必假设所有提供商都能逐 token 输出或接受相同工具；同协议连接仍可配置化扩展。 | [Q07–Q08](question-bank.md#q07)、[案例一](system-design.md#case-1) |
| 10–15 分钟 | 长对话如何记住信息，又控制成本？ | 原文保存在本地，发给模型的是受预算约束的历史和摘要；学习资料按当前授权加入。工具请求与结果不能拆开，摘要来源哈希也不证明内容正确。CLI 与桌面共用策略，但输入长度上限仍有差异。 | [Q13–Q18](question-bank.md#q13)、[案例二](system-design.md#case-2) |
| 15–20 分钟 | 工具超时后为什么不能直接重试？ | 请求可能已在外部成功，只是回执没收到。知行保存执行意图和检查点，对未知写入结果暂停自动重放；恢复先核实权限及实际结果。取消能阻止后续动作，不能撤销已经发生的写入。 | [Q25–Q29](question-bank.md#q25)、[案例四](system-design.md#case-4) |
| 20–25 分钟 | 团队怎样合作，为什么可能更差？ | 主 Agent 分工，最多两名只读成员按依赖执行，再核查和综合；预算、报告与恢复都要记录。错误分工、上下文缺失、截断和错误综合会抵消多模型优势，必须与单 Agent 及自检方案做同题对照。 | [Q31–Q37](question-bank.md#q31)、[案例三](system-design.md#case-3) |
| 25–30 分钟 | 如何证明做得好？ | 工程测试证明契约行为，真实模型评测衡量指定任务上的回答，学习试验衡量用户的理解和保持。814 项测试与四题 20 次历史运行是不同统计单位；知行尚未证明真实教学收益。 | [Q49–Q58](question-bank.md#q49)、[案例五](system-design.md#case-5) |

## 每题怎样读

题库每题都提供 **口述答案 → 知行具体怎么做 → 分析与取舍 → 追问及答案 → 源码与测试索引** 这些内容。先读文字建立理解，再查看索引中的实现与失败测试；索引负责核对，答案本身不依赖先打开代码才能看懂。

第一遍只读“口述答案”和“知行具体怎么做”；第二遍遮住“追问答案”练习复述；第三遍打开源码和测试，检查自己能否解释一个失败路径。系统设计案例另外提供完整口述示范、当前落地方式和多轮追问解答。

## 阅读顺序

1. [岗位要求与项目匹配](job-market.md)：11 个相关岗位样本、能力矩阵、项目优势与缺口、14 天准备安排。
2. [问题与参考答案](question-bank.md)：60 道主问题，逐题包含项目实现说明、追问答案、分析、取舍与代码依据。
3. [系统设计与项目讲解](system-design.md)：六个案例的完整解答、口述示范、追问答案，以及项目介绍和故障故事。
4. [来源与证据边界](sources.md)：招聘原文、页面限制、项目事实与技术资料的区别。

若时间有限，先练习通用接入、Agent loop、工具权限、长对话、执行恢复、多模型团队、评测公平性和性能预算，再进入云端系统设计。基础薄弱时先补数据结构、异步调用、HTTP/SSE、事务、LLM token 与采样概念。

## 一次模拟面试

| 时间 | 内容 | 合格表现 |
| --- | --- | --- |
| 0–5 分钟 | 项目介绍与架构图 | 说明学习目标、模块化单体、共享内核与当前能力 |
| 5–20 分钟 | 选4道核心题追问 | 能从契约走到源码/测试，不只说框架名称 |
| 20–35 分钟 | 选1个故障或系统设计案例 | 先澄清假设，列出状态、失败与替代方案 |
| 35–45 分钟 | 评测与 trade-off | 不混淆工程测试、模型质量和教学收益 |
| 45–60 分钟 | 小型编码或最小复现 | 自己实现、解释失败测试，并说明复杂度与限制 |
