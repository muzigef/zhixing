## B01：资料查询与引用

新增 CLI：

```text
查询资料 <topicId> <问题>
```

验证结果：

```text
查询资料 rag 不存在的独有术语
-> insufficient_evidence：当前主题资料中没有足够证据。

查询资料 rag 实时 渲染
-> 返回 3 条当前 rag 主题的 FTS5 证据
-> 每条包含 实时渲染第四版-CN.pdf#page=<n> 引用
```

输出会裁剪为每条最多 360 个字符，避免大 Chunk 淹没 CLI 和未来模型上下文。

## B02：Run 与审计

每条 CLI 命令创建 `runId`，在 `data/audit/<topicId>/<date>.jsonl` 写入：

```text
run_started -> run_finished / run_failed
```

验证了 `topicId`、递增 `seq`、API Key/token、邮箱和用户绝对路径的脱敏。审计目录已受 Pi 工具守卫保护，模型不能直接读取或改写。

## B03：Reviewer 与进度状态机

新增确定性证据门：实现、测试输出、失败案例和复盘。

- 缺失实现/测试/失败案例：`repair`，学习日不完成；
- 仅缺复盘：`reinforce`，学习日不完成；
- 四项齐全：`advance`，Day 状态原子更新为完成并写入 `PROGRESS.md`；
- 开始 Day N 前必须完成同主题此前 Day；
- `继续` 只返回进行中 Day 的最小下一步。
