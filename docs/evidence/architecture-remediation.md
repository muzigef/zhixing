## N04–N06 · Provider 测量、共享入口与 MCP 隔离

- N04：保留客户端预算；SDK 元数据必须是有效正整数，应用预算与模型限额取较小值后再发请求。Pi 记录 SDK 窗口/输出上限与提交档位；DeepSeek 新增同口径请求/首事件/首文本计时。统计按模型、推理提交值、上下文规模、请求轮数和预算分组，界面可区分。
- N04 定向验证先出现 3 个失败后修复。全量检查暴露旧 DeepSeek 事件断言和缺失必需模型元数据的 SDK 夹具，已更新契约断言与夹具，保留真实 worker 执行检查。没有把新增计时事件删除来迎合旧测试。
- N05：新增排队回归实际复现 invoke 返回下一条排队回答；现按本次 messageId 读取结果。应用回复独立于 Provider InvocationResult，真实轮数/工具数来自持久消息；事件数明确为空，不再伪造 events=0、toolResults=[]。
- N05：依赖检查覆盖间接导入、再导出及动态导入。移除桌面 service 对 prompt 构造器的再导出。发现 CLI “资料问答”仍绕行旧模型链，已移入共享 purpose=evidence；保留无资料时不调用模型。该命令不再悄悄将禁用的真实 Provider 降级成 mock，必须显式切换，和主流程一致。自然语言路由是被允许的纯业务边界，不负责选择历史或模型。
- N06：新增 restricted/读取路径配置，纳入别名与配置授权版本；共用系统沙箱 profile。实际子进程测试同时尝试读取未授权夹具、写出临时目录、连接本机监听端口，全部被拒绝。传统 trusted 模式与受限模式在界面明确区分，read 标签不是安全保证。
- 合并完整 `npm run verify` 退出 0，日志 `/tmp/zhixing-n04-n06-verify.log`；定向日志 `/tmp/zhixing-n04-green.log`、`/tmp/zhixing-n05-green.log`、`/tmp/zhixing-n06-green.log`。N05 专用全量启动时与新测试文件写入重叠导致一次语法检查失败，修正后本次全量覆盖全部切片。

- restricted 暂只支持 macOS；不支持时拒绝连接，不回退到账户权限。目录读取授权包括子目录，用户仍需谨慎限定。

## 本轮真实 Provider 合成检查

仅发送“2+2 等于几？只回复一个数字。”，临时学习/聊天目录，无用户资料。凭据由原产品 Pi SDK 与系统安全存储内部使用，未由工具读取或输出。

- DeepSeek：`node desktop/scripts/check-deepseek.mjs --live`，经已有产品安全存储接口使用已配置模型 `deepseek-v4-flash`，完成且回答 `4`；首文本 2,057 ms，总时长 2,078 ms。单个短请求只证明当次连通，不能代表所有推理档位、长任务或教学质量。
- Pi：`npx tsx scripts/profile-pi-latency.ts --live --output=<临时报告路径> --cases=text-balanced-sse --repetitions=1` 能读取 `openai-codex / gpt-5.6-terra / medium`。第一次总时长 11,519 ms、一次复测 11,415 ms，均失败；安全跟踪为 `http_request_start → http_error`，没有 `http_headers`、文本或用量。不能判定账号失效，也不能将该耗时当成功回答速度。SDK 合成契约通过，真实 Codex 当前连接未通过，需网络链路恢复后复测；本次未改写凭据或模型选择。
- CLI/桌面手动切换 Provider 与重试已由隔离 UI 验收；不因 Pi 失败自动向另一 Provider 外发。
