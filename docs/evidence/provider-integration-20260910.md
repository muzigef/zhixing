## 新增边界验证

- Messages 原生 system/content blocks、签名思考、工具 ID 与工具结果续接；Responses 关闭服务端存储、保留加密 reasoning、使用 call_id 而非输出 item id。
- 两个新协议均经实际 ToolHarness 验证：错误参数被拦截，收到错误结果后模型修正参数，受控工具执行一次；截断工具响应不会执行任何工具。
- 重复工具 ID、缺失工具结果、不完整输出、错误终止状态和联网总开关；失败时已报告用量仍返回，凭证存储或 HTTP 异常不会原样暴露底层错误。
- Gemini 流式工具签名续接只保留允许的字段，任意额外字段不继续转发；自定义连接保留服务商已返回的 reasoning_content。
- 官方进程使用固定可执行文件与 argv，不经 shell；屏蔽 API Key、OAuth token 和任意 Node/SDK 环境覆盖。夹具检查无工具参数，错误登录方式、旧 CLI、原生工具事件、截断和非零进程退出均不能标记成功。
- 实际创建并取消一个停滞的 Node 子进程，确认本机退出；未确认退出的错误单独保留，不冒充停止完成。没有进行真实远端计费取消验收。
- CLI 和桌面都进入同一个 AgentService；实际 CLI 子进程测试通过官方执行器测试替身验证完整历史。共享回复检查最多自动修正一次，持续不合格则 blocked；不因原生进程成功退出而自动认定回答正确。
- API UI 使用隔离 HTTP 和系统加密夹具；原生 UI 使用实际启动的合成进程。验证模板选择、协议选择、空模型 ID、保存与测试、回答、原生程序路径、状态、选择及未工具验证提示。

开发过程中先复现并修复了五个新增失败用例：Responses 失败事件漏记已报告用量、两个协议预检泄露底层凭证存储错误、原生回答未执行输出检查的两个分支。后续迁移测试证明旧 codex-cli 原来绕过新边界，修改注册方式后通过。曾出现的新测试必填字段遗漏和合成凭证字符串触发敏感扫描，也已修正；没有跳过测试或降低扫描标准。
