# 团队输出预算与思考档位优化

日期：2026-09-11。范围：修复此前 Codex + DeepSeek + Kimi 团队中成员因推理耗尽 4096 输出 token 而无法完成报告的问题。此前真实基线在 [三家验收](provider-three-20260910.md) 与 [8 次回归原始记录](team-evaluation-native-codex-regression-20260910161943543.json)。保留旧结果；不修改题目与评分答案。

## 策略与依据

Kimi 官方说明推理与正文共享 max_tokens，K3 始终思考，可通过 low/high/max 调整强度；[官方思考模型文档](https://platform.kimi.com/docs/guide/use-thinking-models)。DeepSeek 官方提供思考开关及 low/high/max；[官方思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)。本轮沿用已有请求映射：DeepSeek 的 quick 为关闭额外思考、balanced 为 enabled/low、deep 为 enabled/high；Kimi 为 low/high/max，不向 K3 发送关闭思考参数。

自动策略只作用于适配器声明推理与正文共享输出预算的成员，支持内置两家与显式配置该推理协议的动态 Chat Completions 连接，不按品牌名或模型字符串猜测能力。原生 Codex 与未知协议保持原有策略。新任务先固定模型连接，再选择资源策略；主 Agent 档位不变。

- 默认整题输出目标仍为 16384，不自动扩大全局额度。先预留分工、审查与最终回答额度，再按成员数计算单次可用份额。
- 当自动成员可用输出额度不足 8192 token 时，采用 quick，默认每次 4096；预算足够时继承主 Agent 档位；均衡建议 8192，深入建议 16384，不够深入但足够均衡时自动选均衡。
- 4096/8192/16384 是本地调度建议目标，不是官方最低要求，也不是准确性或一定完成的保证。Kimi low 仍有推理开销，有限预算仍可能用尽。
- 明确设置的成员思考档位优先；明确设置的输出值作为上限。若整题预算不足，实际单次上限与风险在任务卡中可见，不偷偷重试或更换档位。
- 设置新增整题输出预算选项，成员输出提供“自动分配”。例如两名成员在 24576 的整题目标下各可使用 8192；提高预算由用户选择，可能增加费用与时延。
- 每位成员保存实际档位、策略来源、单次上限和建议目标。新策略会话使用 v13，保存旧文件备份、拒绝旧版本降级覆盖。已有任务继续使用原绑定与旧预算行为，不在恢复过程中改变实验条件。
- 所有实际请求继续走 TeamBudget 的持久预留、实际用量结算、总次数、期限和未知用量规则。单次份额不是整题无限重试许可；多个子任务仍受同一总预算限制。
