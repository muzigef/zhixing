## 本轮实现

- 官方 Codex `AgentExecutor`：通过用户自己的官方客户端与 ChatGPT 登录执行，固定具体模型，不依赖 Pi、不复制订阅凭据、不静默切 API。当前只启用实际验收的 Codex 0.153.4；新版本须先复验空工具请求与权限限制。
- 桌面设置可保存 Codex 可执行文件与模型，macOS 自动查找常用 Homebrew 路径；桌面和 CLI 继续使用同一 AgentService。账号登录由官方客户端处理。
- Codex 禁用内置工具、MCP、插件、hooks、宿主 skills、浏览器、图片及原生子 Agent；使用受限临时目录、官方权限配置和非持久会话。任务输入经 stdin，教学指令文件权限 0600，结束清理临时目录。错误不暴露原生 stdout/stderr 或登录输出。
- 共享团队接受 `AgentBackend`，保留 ModelClient 与 AgentExecutor 的差异。固定模型、只读任务、成员上下文隔离、任务依赖、逐项审查、一次定向复核及恢复沿用同一内核。
- API 请求和官方 Agent 任务分别计数，合计受同一个调用次数限制；原生输出 token 是核算目标，硬限制只覆盖任务数、期限和可见回答字符。实际输入包含运行时开销，累计实际用量超过目标后停止新调用；失败未知用量保留预留。
- 原生团队会话升级为 v12，保留升级前备份；旧版本不能覆盖并丢弃新预算。普通单 Agent 和既有 API 团队保持原版本规则。
- 评测器 v5 支持官方 Codex 作为主模型，使用 `single-codex` / `self-review-codex` 标识。保存固定模型、题集和实际 app.asar 哈希。完整消息交付时间不标成流式首 token 时间。

## 真实评测发现并追加的修复

第一轮 D01 同模型团队正确回答 323，但计划错误地将“只输出任务安排 JSON”作为成员验收条件；随后审查将成员报告格式与自身审查格式混淆，增加一次定向复核和一次重新审查，共 7 次官方任务。保留原始结果，不从统计中删除。

修复同时采用提示边界与程序检查：计划只为原始问题的内容设置交付条件；在成员派发前识别明显的内部阶段/协议检查，若这些协议并非用户问题内容，则使用已有的固定职责回退。用户确实要求设计内部协议、或要求最终答案包含特定 JSON 字段的合法任务仍可通过。成员/审查指令分别说明阶段格式独立，不能将别的阶段输出格式当成问题中的事实冲突。

这是针对可复现的阶段混淆的窄范围校验，不声称能自动验证任意计划的语义质量。对应 `team-task-graph` 和 `team-coordinator` 的新增测试先复现失败，再修复通过；真实前后对照继续使用未改动的题目。

第一轮 D01 异模型团队还有一项独立失败：Kimi 在密钥/连接准备阶段 30.053 秒超时，未发出该成员的模型请求；后续同进程 Kimi 准备只用 2 毫秒，单独回答也成功。此结果不能归因于 Kimi 答题错误，也不能从团队完成率分母中删掉；本次未证明其底层原因是系统授权或其他初始化延迟。


最终验收使用仓库已有 `CI=1` 串行配置；不是放宽超时或跳过测试。794 项 Vitest、两端类型检查、lint、integration、eval、mock smoke、敏感信息与 diff 检查通过（后续仅更正 UI 夹具的阶段识别，避免把规划中的协议说明误认作成员/审查请求）。

第二轮在同一候选应用中显式执行连接预检查：DeepSeek 3.151 秒、Kimi 39.528 秒，均成功后才进入题目计时。预检查单独记录，不将第一轮冷启动失败删除，也不能把连接完成率的变化完全归功于分工修复。

D01 同模型的首个同题复测：7 次任务 → 5 次任务，157.504 秒 → 86.623 秒，答案仍为 323；审查从包含内部格式冲突转为 5/5 内容条件覆盖、无待处理问题。该单题运行不是稳定延迟均值，验证的是已观察到的冗余调用被消除。


修复后的第二轮在 D02 异模型执行中收到应用关闭事件，Playwright 返回 `Target page, context or browser has been closed`；任务按取消落盘，后续组未发出请求。已从本轮固定合成评测的持久报告恢复为 [中断记录](team-evaluation-native-codex-pilot-interrupted-202609101551.json)，明确标注 interrupted，不纳入最终完整运行的质量对照。第一题六组均已完成且字段正确；不能声称整轮通过。随后停止并行 UI 流程，以同一签名包单独重跑。

实际签名包的七组 UI 已全部退出 0：桌面、学习、交互、教学结果、项目、API、团队。UI 修正仅涉及夹具以实际 system 阶段前缀识别请求，不再因提示中提及其他协议而误触发冲突清除；没有放宽产品断言。日志在本地忽略目录 `desktop/.local/provider-three-ui-final.log`。

## 解释与格式辅助复核的范围

开发助手逐条查看了上述 12 条基础题最终回答；这不是独立盲评。D01 六组均说明整数拆分，D02 六组解释均涵盖非负条件、候选根与验根，但 Codex 单次结果字段与解释冲突，仍判失败。还观察到两类格式局限：DeepSeek 两条回答外包 JSON 代码围栏，评分器按既定规则允许去围栏后解析；部分 Codex 数学解释在 JSON 字符串内有重复转义，数值字段正确不代表公式展示质量已经验证。统计表因此只称“字段正确”及“有解释”，不称所有输出格式或教学质量满分。

独立本地核对回归 H02：将冻结题目的代码在 Node v24.8.0 ES module 中执行，退出 0，实际顺序为 `ABHCEGDIF`。H04 的合并比例本地计算为 `12 / 1100 = 0.01090909090909091`。这些核对不作为模型工具输入，也不把答案提供给被测模型。

两套生产依赖分别执行 `npm audit --omit=dev --audit-level=high --registry=https://registry.npmjs.org`，均退出 0、0 个已报告漏洞；没有修改依赖版本或全局镜像。
