## 本轮确认并修复的问题

1. **Pi 实包验收脚本过时**：原脚本固定断言 0.4.1；随后又只观察完整 session 事件，漏掉实际 `message_patch` 活动，误判缺少“等待模型内容”且无法可靠触发取消。改为读取版本元数据、观察真实增量事件、隔离会话、传播错误和有界清理；补同会话记忆、正文流式取消及取消后恢复。
2. **当前问题的回答约束过远**：在 CLI/桌面共享请求链中，针对计算、资料限定和比较加入贴近当前问题的核对规则；保持普通问答不附加无关规则，不增加额外模型审校轮次。
3. **跨行公式排版缺口**：只整理完整、整行边界的显示公式，补齐跨行开闭定界符的换行；不修改公式内容，不处理含混、未闭合或源代码示例。共享会话 patch、最终 item 和重载历史一致。新真实 DeepSeek 推导两次的显示公式格式均通过，内容正确性另行评分。
4. **质量统计误判连接故障**：重复调用导致无进展、最终文本为空，被误计成 provider_failure，并使后续题目未尝试。现在已知任务失败与空回答保留失败并继续下一题；未知错误和执行器异常分开统计，其余无内容失败仍保守停止，不推断连接原因。既有失败原文不改写。

每项均有先失败后通过的边界测试。中途一次全量测试与新增流式取消测试/实现交叠，读取到不一致快照并失败；该次不算通过，最终统一冻结源码重跑。具体命令、退出码和日志哈希见 [工程回执](acceptance-next-engineering.json)。

最终本地 `verify` 通过：131 个测试文件、631 项测试，另跑 integration 9 项、eval 6 项；开发应用五组 UI 通过，两套生产依赖审计均 0 漏洞。已安装应用的 11 项 Pi 实测单独通过。本轮源码尚未替换安装应用，Windows/Intel 与 DMG 的上一轮证据不算本轮重跑。
