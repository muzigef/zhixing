## 数据与执行契约

- 桌面默认建立自己的学习工作区，沿用 CLI 的目录与 Store 格式；用户通过原生目录选择器连接已有工作区。切换不复制、不覆盖历史数据。
- Renderer 只调用受校验 IPC。学习领域控制状态写入，资料通过 Runtime 导入，模型不接触任意文件路径。
- Pi 保持空工具配置；应用预先提供受授权的学习证据。支持工具续写的 Provider 可用同一受控学习工具。
- 目标、用户约束、任务步骤和引用独立于模型上下文保存；重启不自动重放写操作。
- 区分用户声明、实际提交的产物和应用执行的验证。不给布尔标记或未执行的测试标注“已验证”。
- 每个行为切片先补失败/边界测试，运行相关测试及完整 verify；桌面行为额外跑真实 Electron UI，交付安装包前跑实际打包应用。

## 外部验收边界

Apple 签名/公证需要开发者证书；Windows 实机、远端 GitHub Actions 和 Pi 登录成功需相应环境。先完成可执行代码与流水线，不能把配置存在记为真实平台验收通过。

本地实现与 macOS 0.3.0 验收已完成，详细命令、结果和外部待验收范围见 [Evidence](evidence/agent-upgrade.md)。提交与远端工作流状态以 Git 和 GitHub 记录为准。
