# 四组开发评测与配对统计

2026-09-18 新增 `expanded` 开发集 X01–X12；历史 D/H/Q 题目未修改。新题由开发者编写，答案和规则已暴露，不能称为未知保留集。覆盖检索、截止时间、派生验证、未知用量、事务、资源约束、随访缺失、路径授权、相关错误、实验外推、概率预测误差和幂等身份。

```bash
node desktop/scripts/evaluate-team.mjs --live --lead=native-codex --suite=expanded --repetitions=1 --preflight
# 可限定开发探针；报告会记录实际选择，不伪装为完整 12 题
node desktop/scripts/evaluate-team.mjs --live --lead=native-codex --suite=expanded --cases=X01,X09 --repetitions=1
```

默认使用已安装应用；验收当前源码时先打包，并以 `ZHIXING_DESKTOP_EXECUTABLE` 指向对应包内可执行文件。报告记录包哈希、题源文件哈希、完整题集哈希、选择后的数据集哈希和实际模型绑定。不得把安装版运行归因于未打包的新源码。脚本强制隔离评测模式：新建临时会话/工作区，只通过产品接口读取系统应用目录已有凭据及经过 schema 验证的偏好，不迁移原工作区、不允许修改凭据、不开放普通聊天和工具执行。不会为了评测创建或替换签名证书。

四组为单 Agent、同一主模型五轮自检、两个同模型成员的团队、DeepSeek/Kimi 成员与 Codex 主 Agent 的异模型团队。每组最多 12 次请求、240 秒；成员 180 秒；每次输出目标最多 4096 tokens，共享输出核算预算 16384。原生 CLI 的 token 仅在返回后核算，可见字符与任务数/期限受控，不能称为供应商硬 token 上限。各组实际调用不同，也不能把相同预算上限称为等算力。

报告版本 7 保留旧逐次胜平负 `comparisons`，新增 `pairedComparisons`：先匹配同一道题、同一次重复；每题对重复取平均；再按题重采样 2000 次。只有 1 题时不报告区间。缺失配对单列，未完成回答交付分计零；重复回答不增加题数。符号检验为未校正多重比较的探索性统计；这些开发题不能证明总体改善、题目独立或教学收益。

`summary.correct` 从本版本起只计已完成且字段全部正确；`meanFieldScore` 保留可解析文本的原始字段分，`meanDeliveredFieldScore` 则将未完成交付计零。解释长度检查仍只说明“存在解释”，独立语义评分另行导入。`attempted` 由实际请求记录判断，供应商不可用或取消不会被记成成功。

X05 的数值用内存 SQLite 事务执行核对，X09 用共同原因的状态枚举核对，X11 用独立平方误差计算核对。Brier 分数衡量综合概率预测误差，两例更低不能单独证明模型总体校准更好。
