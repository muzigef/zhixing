# 教学效果实测执行说明

当前状态：工程流程可执行，真实招募与独立评阅尚未开始。不得将演示、开发者合成作答、模型自评或单次回答质量当作学习效果。本协议保持单 Agent 实验条件；团队回答质量对照及模型接入工程验收不能代替本研究。

## 负责人开始前填写

记录负责人、参与对象与既往经验、招募日期、统一学习时间、目标主题、题库版本、完整构建哈希、Provider/模型/思考档位，以及资料分享同意。只用参与者代号；身份对应表由负责人单独保管，不提交 GitHub。告知退出方式、数据用途、谁能访问原始回答，参与者可拒绝分享而继续本地学习。

先开展可行性试用，检查流程负担、问题歧义和失访原因。试用人数由可用条件决定，不能把小样本描述当有足够统计把握的比较。若要研究因果效果，需在收集前确定主要指标、样本量依据和随机分配方案；当前应用记录的是学习者选择，不能事后改称随机对照。

## 每位参与者的实际步骤

1. 使用同一冻结构建，在「学习效果验证」中选择完整产品协议，确认模式及主题。按本人实际状态填写学前答案、解释、新例子和是否使用帮助；不会可以选择「暂时不会」。
2. 进入专属教学对话，按预先约定时间学习。保持模型、思考档位、预算和资料访问条件；改变条件需保留记录，不能混入同条件主分析。
3. 结束学习后独立完成学后检查。记录操作困难、歧义题和中止原因，不能由指导者代答或提前透露标准答案。
4. 在应用允许的 72 小时后完成延迟复习，记录实际延迟。提前复习、额外学习、看过答案均如实注明；不修改系统时间绕过门禁。缺失延迟保持缺失，不填零、不只报告完成者。
5. 经参与者同意，通过应用导出验证结果。汇总使用 `npm run eval:learning -- export1.json export2.json --output=summary.json`，保留借助帮助、重复练习、失访和排除原因。

## 独立双人评阅

对已经 complete 或 abandoned 的记录运行：

```sh
node --import tsx scripts/create-outcome-review-pack.ts exported.json --output=review-pack
```

仅把 `reviewer.json` 分别给两位评阅者。`coordinator-private.json` 由负责人单独保管，不能跟包共享。工具随机打乱题目，隐藏模型、学习方式、阶段、自动分数、时间和已有评分，保留原始解释；分享前检查解释中是否自带身份/模型信息。本工具是辅助盲评，不能自动证明匿名性或评阅独立性。

评阅者先分别判断概念正确性、理由是否支持选择、能否迁移到新例子，并引用具体句子说明 supported / partial / unsupported。先冻结两份独立记录，再讨论分歧；不要求第二人接受第一人的意见。负责人按映射回到应用录入实际署名、判断与依据，核对原文哈希和最新修订，保留修订/撤回历史。空评阅包和零人工评价不能当已验收。

## 题卷校准与验收门槛

按主题、卷别、阶段和模型条件查看题目歧义、答对率、解释与选择是否一致，以及用时分布。不同卷均分相近不证明等难；学后表现还受教学影响，不能直接与另一卷学前均分比较。先由领域评阅者核对内容，再设计独立的题卷次序平衡试用；改题需升级题库版本，旧数据保留对应旧卷，不静默重算。

工程验收通过意味着原始记录、来源绑定、去重、缺失、排除、双人分歧和导出可核查。研究验收还需要真实完整记录、两位独立评阅及实际延迟复习，由负责人确认参与身份和帮助使用。当前没有这些数据，因此尚不能给出教学有效、优于通用 Agent 或题卷等难的结论。
