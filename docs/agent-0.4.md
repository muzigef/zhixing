# 知行 0.4 使用与实现说明

0.4 延续学习 Agent 的定位，改进连续交互、受控执行、检索和数据可恢复性。功能验证与真实回答质量分开记录，不能据此宣称达到 Codex 或 Claude Code 的整体水平。[执行计划](agent-next-plan.md)与[本轮证据](evidence/agent-next.md)保留范围和验证结果。

## 连续对话与模型

设置支持 Pi · Codex、DeepSeek API 和离线演示。Pi 沿用已有模型偏好，认证由 Pi SDK 自己处理；读到模型配置不代表真实请求成功。失败后可在同一会话切换 DeepSeek 重试。默认均衡思考，输入框可独立选择快速、均衡、深入思考；篇幅仍由回答风格与本轮要求决定。

| 档位 | DeepSeek | Pi Codex |
| --- | --- | --- |
| 快速 | 关闭 thinking | low |
| 均衡 | thinking + low | 保留 Pi 中配置的强度 |
| 深入思考 | thinking + high | high |

system、用户与助手历史、当前请求分别传输。目标、摘要、资料属于补充上下文，不能改变权限。普通概念题不附带无关的空任务状态；请求查看进度时提供实际前置阻碍。较早历史的摘要在回答结束后后台整理，新输入会取消旧整理。按模型与思考档位显示首字耗时、总耗时及 Provider 报告的 Token 用量；没有虚构费用。Pi 每次模型回合启动独立 worker，目前未实现持久连接池。

问题卡可以选择或输入回答；操作卡展示即将保存的具体代码/文本，可允许一次、允许本会话或拒绝。任务等待回复时会保存状态。编辑用户消息会创建新分支，原会话保留；新分支不继承写入授权。回答对比支持 Markdown、代码和公式。

## 应用工具与持久任务

先选择主题，并按需要启用“本会话使用学习上下文”。Pi SDK 和 DeepSeek 均可请求同一组应用工具：进度、资料目录/检索、技能列表/读取、任务步骤/状态、保存产物、运行实验。写入和执行由应用授予权限，模型无法自行提升权限。

`assistant_tasks` 保存计划和完成标准，`assistant_operations` 保存输入、实际结果与运行状态。完成标准仅包括实际保存产物或测试退出码为 0；模型声明不算完成。恢复同一任务时可复用操作结果；相同保存内容不会因步骤改名而重复生成，命中缓存后仍核对产物完整性。失败结果可重试。队列、停止、切换模型与继续仍保留在原有会话中。

实验执行仍限定为当前学习日的 JavaScript 实现与 `node:test` 脚本，使用操作系统隔离；平台不支持时明确失败，不会降级为无隔离执行。没有任意 shell、文件浏览或 Git 操作工具。CLI 的 Pi 适配仍是文本模式，桌面采用 SDK 模型桥接。

## 资料、引用与技能

默认检索使用中文分词、双语同义词、关键词候选与确定性重排，并补充相邻片段。旧哈希向量表保留兼容，不把哈希碰撞作为语义证据。回答实际带有已知来源标记时显示“已引用资料”；其余候选收起展示。标记匹配只证明位置可定位，不能证明每一句话都有资料支持。

可选本机语义检索：在设置填写已经安装的 Ollama 嵌入模型名，再到“课程与资料”点击“构建本机语义索引”。应用仅访问 `127.0.0.1:11434`，不下载模型、不跟随重定向。每次请求检查安装的模型版本，嵌入前后版本不同则拒绝结果；模型版本与片段内容改变会使旧索引失效；未启用或模型不可用时保留关键词检索。每次索引最多 5000 个片段。本机服务与实际语义效果需要单独验证。

“课程与资料 → 学习技能”显示共享和当前主题技能。可预览完整流程，再带入输入框。内附技能首次复制到工作区，不覆盖已有自定义文件；技能是参考文本，不是权限来源。模型亦可按需调用 `list_skills/read_skill`。MCP 尚未建立连接：现有 ToolHarness 是未来适配入口，接入前须确定服务、数据范围与认证方式。本轮没有未经配置的外部服务。

## 学习结果与复习

“独立检查”提供内置四个主题、各三个学习日的 24 道概念与反例检查题。实际作答、错因、解释及复盘单独保存。未通过后 1 天复习，首次通过后 3 天，已有通过记录后再次通过为 7 天。自定义主题没有题库时明确提示，不能伪造评分。

界面分别展示证据完整性、本地测试结果和本次知识检查结果。检查通过仅说明本次题目表现，不代表完全掌握，也不会直接改变课程完成状态。产物 Review 仍按原有规则执行。

## 全量备份与版本兼容

设置中的“备份全部学习数据”导出一个独立文件夹：当前工作区的资料副本、inbox、课程、技能、本地设置、笔记/证据、审计及一致的 SQLite 快照，加上此设备的全部会话和偏好。密钥、认证文件与应用运行缓存不导出。备份未加密；应自行选择合适的保存位置。上限为 2 GB、20000 个文件，符号链接会拒绝备份。

“从备份恢复”先验证清单、路径、逐文件 SHA-256 和数据库版本，再展示文件数确认。恢复到新工作区，会话使用新编号，原工作区和会话保留。当前模型密钥与偏好不覆盖；备份中的 preferences.json 作为存档保留。只将属于已备份工作区的会话绑定到恢复目录，其他工作区的历史保持原关联；写入/资料授权均重置，队列暂停，不自动发模型请求。失败时保留新目录中的未完成副本以便检查，不删除原始数据。

会话 schema 升到 v2；读取 v1 不立即改写，在首次保存前保留 `.json.v1.bak`。数据库采用追加迁移标记 v4，拒绝高于支持版本的数据，不做降级。完整工作区备份与 CLI 原有“仅数据库备份”是不同入口。

## 构建、分发与验证范围

桌面版本为 0.4.0，运行时内附 Electron、Pi SDK 和 SQLite。macOS arm64 本地安装文件位于 `desktop/release/`，不随 Git 源码提交。构建和验证命令见[测试指南](TESTING.md)。

发布工作流覆盖 macOS arm64、Intel Mac、Windows x64，均配置实际包 UI 验证。Intel 标签采用 GitHub 的 `macos-15-intel`，见[官方 runner 列表](https://docs.github.com/en/actions/reference/runners/github-hosted-runners)。本机验证不能替代其他平台或远端 CI 结果。

手动触发发布流程时可选择 `sign_macos`。需先配置仓库 Secret：`MAC_CSC_LINK`、`MAC_CSC_KEY_PASSWORD`、`APPLE_ID`、`APPLE_APP_SPECIFIC_PASSWORD`、`APPLE_TEAM_ID`。缺少必要配置会失败；启用后强制签名并校验公证票据。凭据只交给构建器，不写进源码或产物清单，规则参考 [electron-builder 签名与公证](https://www.electron.build/v26/docs/features/code-signing/notarization/)。当前本地包未获得 Developer ID 签名和 Apple 公证。
