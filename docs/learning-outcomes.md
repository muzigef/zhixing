# 学习效果验证

2026-09-08 按 0.8 实现更新。入口：桌面「课程与资料 → 学习效果验证」。0.6 支持完整产品能力和原提示方式两种试验协议；也可以从源码运行 `npm run desktop`。这里记录选择题表现、文字解释和延迟复习，不自动认证掌握，也不改变课程完成状态。

## 使用流程

1. 选择 Agent 开发或 RAG 主题，选择验证范围（默认完整产品能力），再选择「知行引导教学」或「同模型直接聊天」。每个主题只允许一个进行中的验证；可以结束并保留已有记录。
2. 完成学前检查：3 道情境选择题，可选「暂时不会」；用自己的话说明理由并给新例子；明确选择独立作答、使用提示/资料或看过答案/借助 AI。
3. 进入专属学习对话。使用设置中选择的 Pi Codex、DeepSeek API 或演示 Provider，支持流式回答、追问、停止和重试。至少完成一轮模型回答后，回到课程面板点击「结束学习，开始学后检查」。尚有待发送消息、最后一轮失败或中断时，需先处理这些状态。
4. 完成另一组情境的学后检查。应用使用提交时的本机时钟安排 72 小时后的延迟复习；提前请求由领域服务拒绝。到期后刷新面板并开始复习。可以在课程面板另设每日复习提醒；它只在程序运行时检查，不是针对该验证记录的 72 小时专属通知。
5. 延迟复习使用第三组情境，提交后显示该组解析。关闭应用后可继续，全部备份恢复会保留验证记录并重建学习对话关联。

每主题提供 3 份各 3 题的预置情境卷，开始时随机排列使用顺序并持久保存。覆盖「模型声明与实际执行、授权边界、取消状态」及「引用支持、证据缺失、检索内容指令边界」。题库难度和不同题卷的可比性尚未通过真实学习者校准，结果不能推广到整个学科。

## 对照条件与统计边界

两种协议分别保留：

- **完整产品能力**：知行组使用正常产品的教学策略、上下文和工具流程，学习资料、项目、MCP 仍由学习者在会话中分别授权；直接聊天组仅使用本次目标和本段会话，不开放产品工具和个人学习状态。记录每轮实际授权与工具次数，未授权能力不会自行开启。
- **仅提示方式**：沿用原对照，两组均不开放应用工具或学习状态，仅比较是否增加引导教学提示。旧记录缺少协议字段时按此解释，不转换成完整产品证据。

两种协议均不自动向模型发送学前/学后/延迟检查题、作答或解析。学习对话本身会发送到所选模型；学习者手动粘贴的内容仍属于主动发送。比较对象是同一模型下的知行使用方式，不能解释为与商业 Codex/Claude Code 的直接产品对照。

系统按主题、试验协议、题库版本、实际 Provider、模型 ID、思考档位、篇幅、上下文预算和构建哈希分组，报告学前与学后、学前与延迟复习的平均答对比例变化，单位为百分点。统计单位是验证记录，不是已核实身份的独立参与者。只纳入首次参与且两次均自报独立作答的成对记录；缺少延迟结果显示为空，不填零。演示、未知模型、完整产品构建缺失或变化、学习中切换条件、使用帮助、重复参与及已结束未完成的记录保留，汇总注明排除原因。

学习方式由用户自选，不是随机分组。使用同一模型不会消除已有知识、学习时长、提示内容、题卷难度、其他渠道帮助等差异。本机时钟也不能防止系统时间被调整。报告只描述观察到的成绩变化，不提供显著性检验、自动胜者、因果结论或掌握认证。

## 导出与多人汇总

「导出验证记录（含作答）」通过文件选择器保存 JSON，包含本人解释、答案、帮助声明、题卷 ID、时间、协议、实际授权/调用数和构建来源，用户自行决定是否分享；无自动上传。导出不含未展示题卷的答案键、凭据或学习对话正文，原学习对话保留在应用中。

收集参与者自愿提供的导出文件后，可以本地汇总：

```bash
npm run eval:learning -- export-a.json export-b.json --output=summary.json
```

最多处理 100 个导出文件、每文件 4 MB 和 50 条记录；输出文件必须尚不存在，不覆盖输入。省略 `--output` 时打印到终端。汇总按持久验证 ID 去重；同一次记录后续导出使用较新的快照，备份副本不增加样本数。身份字段或已有作答冲突、分数不符题库、跨主题混入及未来格式均拒绝。汇总输出只有分组统计和限制，不复制原始文字作答。

请保留未完成、借助帮助和重复参与的数据，用于了解掉队情况及练习需求。学后检查完成后结束验证，已有合格的学前／学后对照仍计入，缺少的延迟结果保持为空，避免只统计完成全部阶段的人。不同人换设备或创建独立工作区产生的新 ID 无法自动识别，统计前仍需人工核对参与情况。

## 文字解释的人工复核

程序只自动评分选择题。文字解释最初标为 `pending_human_review`；验证完成或结束后，可以在应用中录入署名复核、判断和理由，并修订或撤回。每条复核绑定当时的解释原文哈希和修订号，保留历史，不改写选择题分数、不交由模型自评分，也不加入教学对照上下文。署名身份为自报，不自动证明评审独立性。取得分享授权后也可用导出文件做独立复核，建议隐藏学习方式和模型。

| 维度 | 0 分 | 1 分 | 2 分 |
| --- | --- | --- | --- |
| 概念准确 | 核心概念错误或未解释 | 大体正确但有遗漏 | 关键概念与条件准确 |
| 判断依据 | 仅重复结论 | 给出部分原因 | 能说明证据、适用条件和错误选择的问题 |
| 新情境应用 | 无例子或照搬题干 | 有新例子但应用不完整 | 能将原则用于不同情境 |

这是待试用的标准，不是已验证量表。复核记录应注明记录 ID、阶段、复核人、各维度分数、依据及分歧；不把自评当成独立复核。

## 后续验证优先级

1. 由真实学习者完成学前、学后和 3 天复习，观察流程负担、掉队位置和帮助使用情况。
2. 独立复核解释，检查选择题高分是否伴随正确理解；收集歧义题，修订时提升题库版本。
3. 校准题卷难度，明确参与对象、分组与分析规则后再开展有足够样本的对照，个人自选记录不能替代该过程。
4. 依据真实错因完善教学反馈和新情境练习，再扩展主题。

## 0.8 报告质量与校准记录

汇总同时展示有效配对数量、缺失延迟记录数，以及分数变化的均值、最小值、最大值与样本标准差；少于两条记录时标准差为空。分散程度不是因果证据，也不是置信区间。题卷按主题、题库、卷别、阶段和实验条件分别描述，校准状态明确为 `uncalibrated`，不把观察均值当等难证明。

人工复核按每位署名者最新的有效修订计数，区分待复核、单人、至少两人，以及是否存在判断分歧；署名仍是自报身份。独立双人流程应先隐藏学习方式/模型，各自复核，再记录分歧和修订依据。累计导出允许追加复核，但必须保留旧历史且符合递增修订、来源原文哈希及最新状态；篡改历史或冲突快照拒绝合并。

这些是数据质量工具。真实参与者、独立评阅身份、题卷等难性和 72 小时保持效果仍需实际采集与校准，不能由自动测试代替。当前验收见[架构修复证据](evidence/architecture-remediation.md)。
