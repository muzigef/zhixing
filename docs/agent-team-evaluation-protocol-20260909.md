# 团队回答质量：冻结评测协议

> 历史计划或版本记录：下文保留当时的设计、范围及验证结果，不是当前功能清单或新的开发指令。现行实现、已完成的后续改动与待验收项见 [当前状态](current-status.md) 和 [文档导航](README.md)。

冻结时间：2026-09-09，首次真实团队评测之前。数据与评分器为 `src/team-evaluation-cases.ts`；每次产物保留其 SHA-256 与运行版本。题目均为合成数据，不使用个人会话或学习资料。

## 对照条件

普通单 Agent（Pi Codex）、同一会话中连续两次额外自检的单 Agent（Pi Codex）、同模型团队（Pi 主模型及两个同模型成员）、异模型团队（Pi 主模型、DeepSeek 与 Kimi 成员），另加 DeepSeek/Kimi 单 Agent 基线。共六组；每题每组重复两次，按固定轮换顺序执行。主模型实际 ID 从 Pi 配置冻结，各 API 使用产品配置的模型。禁止失败后静默换模型。

先跑两道开发题确认真实通路；开发题不进入留出结果。留出题八道，覆盖条件概率、事件循环、带依赖的组合优化、资料约束、梯度计算、逻辑一致性、初学者解释及事务并发。每组十六个留出回答，共九十六个根任务。团队至少实际调用每个配置成员一次；缺失成员不得计为完整团队成功。

共享 AgentService 负责所有请求。普通单 Agent 每请求最多 4096 输出 token；自检组最多三次根回答、合计最多 12288；团队每题最多十二次模型请求、16384 输出 token 和 180 秒，单成员最多 60 秒。真实请求量与已报告用量全部记录；这些是生产默认策略下的资源对照，不宣称严格等算力。Pi 同一连接暂按串行执行。订阅成本未知，不能记为零；不猜测 API 账单。

## 评分与报告

用户题明确要求 JSON 答案与中文解释。确定性评分检查数值、集合、执行顺序、资料边界和逻辑条件；数值容差要求绝对误差不超过 1e-9，且非零标准值的相对误差不超过 1e-6；题目明确要求非整数至少保留十二位有效数字，避免舍入歧义。解释是否存在单独记录，不将字数或关键词当作教学质量认证。额外依据题目明确列出的解释要点做开发复核，保留原文；这不等于独立人类盲评，也不证明真实学生学习效果。

所有失败、超时、截断、无法解析及团队部分完成均留在分母中；同时报告内容正确率与完整成功率，避免正确片段掩盖运行失败。记录模型绑定、首字时间、总时间、模型请求数、工具请求数、输入/输出/缓存用量及缺失情况。自检组保留每次回答，团队保留每个成员结果。比较每道题的配对胜/平/负及平均成绩，不用少量样本宣称统计显著或普遍优越。

结果只支持有限工程样本的结论。若团队没有稳定改善或更慢，维持单 Agent 默认，团队标为实验性，并明确适用条件。评测后的修复须保留原运行记录，使用新的运行 ID，不覆盖或删除不利结果。
