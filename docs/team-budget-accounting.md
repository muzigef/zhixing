# 团队预算核算

2026-09-18。共享 `TeamBudget` 在每次调用前持久化逐请求输入/输出预留，再允许 API 或原生执行器派发。缺少回执、取消和中断都保留未知预留；恢复读取同一账目，不把未知算成零。

输入核算是“已报告输入 + 每个未知请求的预留”，不再对两个不相关的合计取最大值。有效回执只能结算对应请求；整数、非负、每次最多一份汇总，重复或异常回执不释放预留。正常终止前暂存 API 用量，避免重复回报被上层累计。存储失败后禁止继续派发。

已观测的估算误差按连接/模型身份用于后续预留：保留最大正开销与最多四倍比例，取较保守值；记账保留原估计和实际值。首次请求仍只有启发式估计，远端隐藏提示、原生 Agent 内部步骤及计费规则不可完全观察，所以这不是金额或首次调用的硬 token 上限。API 输出参数依赖服务商遵守，原生输出目标仅限制可见字符/任务数/期限；超出实际预算后不再发起调用。

旧任务没有逐请求明细时，未知部分暂保留全部旧估计，与已报告用量相加。这可能提前停止，但不能假定旧估计与已知回执一一对应。新账目与旧汇总字段必须一致，否则拒绝续跑，不自动修复用户记录。

验证见 `tests/team-budget-accounting.test.ts`、`tests/team-budget.test.ts`，覆盖混合用量、重启、篡改、旧格式、重复/小数、实测校准、并发取消及落盘失败。
