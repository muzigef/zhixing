# AI 自动开发、验证与测试协议

> 状态：已确认
> 适用范围：`zhixing/` 内的 MVP 开发。此协议优先于“只写设计、不落代码”的默认工作方式。

## 1. 授权范围

AI 被授权在 `zhixing/` 内自主完成：创建和修改源代码、测试、配置、主题计划、Skill、非敏感测试夹具、文档、评估报告和脱敏 Evidence；安装项目依赖；运行 lint、typecheck、单元测试、集成测试、Eval、mock smoke 与纯本地资料导入。

AI 不得自主执行：Git commit/push、访问或导出浏览器 Cookie/账号 token/CLI 凭证、写入 API Key、关闭纯本地模式、将用户资料发送给外部 Provider、删除用户资料或主题、调整本机系统权限、安装全局软件、执行未列入项目脚本的破坏性 Shell 命令。

## 2. 不可违反的开发约束

1. **范围约束**：优先完成 [任务台账](../TASKS.md) 中首个未完成切片；不以框架替换、范围外扩展或多 Agent 来逃避当前缺陷。
2. **契约先行**：修改公共行为前先更新或新增 TypeScript/Zod 契约、测试和相关文档；`topicId`、权限、引用、隐私和记忆写入规则不得只依赖 prompt。
3. **测试先行**：每个行为修复或新增能力至少先新增一个失败/边界测试，再做最小实现；真实模型不作为必需测试前提。
4. **最小权限**：资料只能从 `inbox/<topicId>/` 显式导入；写入只能通过受控 Store；默认纯本地；所有路径先经 `PathPolicy`。
5. **敏感信息零落盘**：不得在源码、测试、settings、日志、Evidence、错误信息中写入 API Key、token、Cookie、邮箱、手机号或仓库外绝对路径。
6. **用户资料零直读**：模型工具不得直接读取或改写 `inbox/`、`data/`、`db/`、`learning-notes/`；资料只可由受控本地 Runtime 处理。
7. **质量门禁**：不得使用 `it.skip`、`it.only` 或吞掉失败退出码；每个切片完成前必须运行 `npm run verify`。
8. **可复现**：每项完成都必须有可执行命令、退出码、测试名或 Evidence；不能以“模型回答合理”替代验证。
7. **诚实状态**：只能报告实际运行通过的命令和测试。未实现、跳过、环境失败和已知风险必须明确记录。
8. **小批次提交**：一次只处理一个可验收切片；完成后先运行受影响测试，再升级到 lint/typecheck/全量项目测试。

## 3. 标准执行循环

```text
读取契约、计划、已有测试和当前 Evidence
-> 选择首个未完成且可验收的切片
-> 写或更新失败测试
-> 最小实现，不扩大边界
-> 运行定向测试
-> 修复至通过
-> 运行 lint + typecheck + 相关集成/Eval
-> 检查敏感信息、路径隔离和文档同步
-> 追加 Evidence，更新计划状态
-> 选择下一个切片
```

每个切片的完成记录必须包含：目标、改动文件、验证命令、关键结果、未验证项、风险和下一切片。

## 3.1 自动续航规则

用户已授权主 Agent 在完成一个切片后自动继续 [全量开发计划](development-plan.md) 的下一项，不需要逐项等待确认。执行顺序由当前台账的“当前下一项”决定；每个切片完成后，AI 必须更新状态与 Evidence，再立即开始下一切片。

自动续航只在以下条件之一出现时暂停：本协议第 6 节的必须暂停条件、全部完成定义已满足、或运行环境主动终止会话。AI 不得把“已完成基础闭环”“已更新文档”或“单个测试通过”误报为整个项目完成。

## 4. 固定实施顺序

1. CLI 资料查询与引用展示。
2. Run 生命周期和脱敏 JSONL 审计。
3. Reviewer 状态机、证据 schema、主题进度原子更新。
4. 资料异常路径：损坏/加密/扫描 PDF、取消、事务回滚、配额。
5. 记忆管理 CLI、删除影响预览和基础备份。
6. Codex 官方 CLI adapter：白名单 argv、超时、取消、结构化错误、mock fallback。
7. E01–E31 评估集补齐并全量执行。
8. 可选真实 Codex smoke：仅在不外发用户资料、命令可见、用户当前授权仍有效时运行。

## 5. 验证门槛

每个代码切片至少运行：

```bash
npm run lint
npm run typecheck
npm run test
```

触及 CLI、资料库、SQLite、记忆或状态机时，额外运行：

```bash
npm run test:integration
npm run eval
npm run smoke:mock
```

涉及真实 Provider 时，mock 测试必须先全部通过；真实 smoke 只验证连通性和脱敏行为，不输入用户资料，不把模型输出当作功能验收唯一证据。

## 6. 必须暂停并向用户报告的条件

- 需求与已确认决策、数据契约或主题隔离边界冲突；
- 需要提升资料/费用/并发配额，或需要关闭纯本地模式；
- 需要真实 API Key、需要重新登录官方 CLI，或官方 CLI 协议无法安全调用；
- 需要删除、迁移或覆盖用户资料、历史记录、数据库；
- 三次最小修复后同一测试仍失败；
- 需要新增范围外依赖、全局安装、系统权限或网络服务；
- 全量 Eval 未通过但计划要求宣布 MVP 完成。

暂停报告必须包含：阻塞点、影响范围、已尝试步骤、可选方案、推荐方案和所需确认。

## 7. 完成定义

只有以下条件同时满足，AI 才能把 MVP 标记为完成：

- 功能设计中的 E01–E31 已实际通过；
- lint、typecheck、test、integration、eval、mock smoke 实际通过；
- Evidence 包记录关键命令、资料引用、失败路径和已知限制；
- 文档、契约、测试与实现一致；
- 无敏感信息扫描命中；
- 可选真实 Provider smoke 的执行或跳过原因已如实记录。
